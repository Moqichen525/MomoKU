# 多视图与视频参考

仅在多视图、表情变体、连续镜头或视频参考任务中读取。目的在于降低可见的设定漂移，不是靠增加图片数量保证一致性。

## 1. 保留一个清楚的角色基准

优先使用用户已确定的原图。原创人物先建立一个基础形象，再扩展角度；可以自行检查后继续执行，除非有需要用户决定的身份或造型冲突。

多张图复用一份简短资料卡，放在随图文本或交付清单中，不必写到图片里：

| 类别 | 记录内容 |
| --- | --- |
| 身份 | 角色名/编号、可靠基准文件与版本、已确认或已检查候选状态 |
| 固定外貌 | 可见脸型和五官关系、眼睛、发际线、头发、年龄感、体型、已有标记 |
| 服装版本 | 内搭、外层、下装、鞋袜、配饰；各自颜色、形状、开合与所在侧 |
| 可变状态 | 当前表情、姿态、道具所在手、衣服湿污或破损、剧情时段 |
| 未知 | 被遮住的细节、没有参考的背面与另一侧；不要写成已核实事实 |

同一剧情时段复用同一套服装版本。明确的换装、剃须、受伤等剧情变化另开版本，不误当作穿帮，也不自动回滚用户要求的变化。多角色时分别记录，不混用脸、身高或衣服。

## 2. 多视图与表情分开做

按用途选择最小有效集合：

- **基础设定**：正面全身、角色自身左侧全身、背面全身；需要脸部识别时补正面和三分之二侧脸近景。
- **左右不对称的造型**：补另一侧；说明是“角色自己的左/右侧”，不能拿镜像代替另一侧。
- **表情组**：默认沿用同一近景角度与照明，按剧情选择几种表情；用户未指定时可采用平静、轻喜、克制愤怒、担忧作为候选，不强制一次生成全部。
- **镜头专用**：转身镜头需要相邻角度，手部道具镜头需要可靠的手与道具关系；不用每个镜头都提交整套设定图。

多视图尽量统一站姿、衣服状态、地面基线和照明，避免遮住脸与关键服装结构。全身组之间保持相近比例；近景是独立构图，不要求与全身组头部像素尺寸相同。不把“三分之二侧脸”标成严格侧面。

新角度里不可见于基准的结构属于补全设计。采用与已知信息兼容的保守处理，并标记为推定；若背部图案、单侧伤疤等会影响剧情，先问清或要求对应参考。

**总览拼图用于审查，独立单视图用于按需输入。** 用户要求一张拼图时照做；同时需要视频素材时，优先保存清晰的单视图并可另作总览。现有拼图可在可用工具允许时裁出单格；裁切不会恢复原本没有的细节。太小或模糊的单格应另做高清候选并再次核对身份，不能称为无损增强。

## 3. 区分视频输入的职责

- **角色参考图**：用于表达人物长相或服装，选择清晰、相互一致且与该镜头有关的图。
- **视频首帧**：就是要开始运动的实际画面，需要正确场景、人物数量、位置、服装状态、景别和比例。不要默认把带分隔线的五视图拼图当成首帧，否则可能把拼图布局带入画面。
- **首尾帧**：在目标工具支持时可用于约束片段两端；中间动作与外貌仍需检查。尾帧应与首帧的衣着、道具和场景状态相容。

未指定视频平台时，先给通用参考包，不阻塞人物设计；到实际接入时再核查该型号的参考图数量、人物限制、首尾帧和尺寸要求。不能假定所有平台都接受多参考图，也不能把不同平台参数互换。

以最近已验收镜头的连续性为依据，记录每个镜头的起始和结束状态，例如：右手拿杯 → 杯子放桌上 → 下一镜双手空着。不要仅复制外貌段落而忽略道具、衣服开合、伤痕或湿污的延续。跨镜头以剧情需要的变化为准，而非要求每帧表情与光影完全相同。

## 4. 交付与验收

文件按角色、服装版本、角度/表情与版本命名，例如 `eduardo_robe01_front_v02.png`。标签含义在清单中说明；不把日期、角色名当成模型会记忆身份的机制。

验收结果按图列为“已检查候选 / 待修正 / 待确认”，用户明确认可后再写“用户确认”。只交付已通过当前检查的图作为推荐参考；待修正图单列，不让视频工具随机选到错误版本。

视频测试先选择一个能暴露主要风险的短镜头，例如自然转头或身体转侧。检查起始、中间、结束及转头、遮挡、拿放物等关键帧；实际查看视频前不能声称已验证无穿帮。发现漂移优先缩小动作幅度、调整参考选择或修正首帧，而不是无限叠加形容词。

## 来源与工作约定

OpenAI 的 [Image prompting](https://developers.openai.com/api/docs/guides/image-prompting) 建议明确编辑变化与保留项、区分各参考图用途、逐次检查。Google 的 [Veo 文档](https://ai.google.dev/gemini-api/docs/veo) 区分参考图引导和首帧动画等用法，具体支持随型号不同。上面的资料卡、命名、多视图选择与检查步骤是本技能的实践约定，不是这些文档给出的通用保证。
